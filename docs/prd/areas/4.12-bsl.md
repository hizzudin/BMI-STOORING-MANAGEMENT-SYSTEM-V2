# 4.12 BSL: parts baseline (P0)

> Part of the BMI Stooring System spec (§4 functional requirements, area BSL). Core rules, roles, state machines, business rules and decisions: [PRD.md](../../../PRD.md). Section numbers and IDs are unchanged from the single-file PRD v2.4.


Goal: give alerts a starting point for vehicles that already have tyres and service parts fitted.

| ID | P | Requirement | Screens | Data | Rules |
| --- | --- | --- | --- | --- | --- |
| REQ-BSL-001 | P0 | THE SYSTEM SHALL let the System Admin enter a baseline without an SPK, right after adding a vehicle or with "+ Parts baseline", in one transaction written to the audit log. | [`PartsBaseline`](<../../../Design Artifact/fleet/PartsBaseline.html#PartsBaseline>) | `vehicle_part_items`, `part_placements` (is\_baseline) | BR-01 |
| REQ-BSL-002 | P0 | THE SYSTEM SHALL let the System Admin pick, per tyre position, a tyre that is In\_Stock (go-live tyres are first received with source Existing), with tread depth and fitting odometer; WHEN saved, the tyre SHALL be Mounted there and leave the In Stock count. | [`PartsBaseline`](<../../../Design Artifact/fleet/PartsBaseline.html#PartsBaseline>) | `tyres`, `part_placements`, `tyre_events` | BR-11 |
| REQ-BSL-003 | P0 | THE SYSTEM SHALL take, per part item type that applies to the class, the date and odometer of the last replacement; the normal life in km and days SHALL come from the master and be editable per vehicle. | [`PartsBaseline`](<../../../Design Artifact/fleet/PartsBaseline.html#PartsBaseline>), [`SettingsPartItemTypes`](<../../../Design Artifact/settings/SettingsPartItemTypes.html#SettingsPartItemTypes>) | `part_item_types`, `vehicle_part_items` |  |
| REQ-BSL-004 | P0 | THE SYSTEM SHALL compute next due (km and date, whichever first) and a status Normal, Due soon, Act now or Missing, and raise one alert per part item near its limit. A part item without a baseline SHALL show Missing and raise no alert \[A\]. | [`Vehicles`](<../../../Design Artifact/fleet/Vehicles.html#Vehicles>) | `vehicle_part_items`, `maintenance_alerts` |  |
| REQ-BSL-005 | P0 | WHILE no SPK has touched a part item, THE SYSTEM SHALL let the System Admin correct its baseline with a reason ("Correct baseline"), logging old and new values and recalculating next due; tyres are never corrected here. IF an SPK has touched it, THEN THE SYSTEM SHALL refuse. | [`BaselineCorrect`](<../../../Design Artifact/fleet/BaselineCorrect.html#BaselineCorrect>) | `vehicle_part_items`, `audit_logs` |  |
| REQ-BSL-006 | P0 | WHEN an SPK completes, THE SYSTEM SHALL reset every part item linked (through the service or part catalog) to a line of that SPK: last replaced date and odometer, next due, source SPK \[A\]. |  | `vehicle_part_items.last_spk_id` |  |
| REQ-BSL-007 | P0 | THE SYSTEM SHALL let a Planner or the System Admin maintain part item types in Settings > Part item types: code, name, category, normal life in km and days, early-failure tolerance (starting value 80%, adjustable, DEC-47), classes, optional PM package. | [`SettingsPartItemTypes`](<../../../Design Artifact/settings/SettingsPartItemTypes.html#SettingsPartItemTypes>) | `part_item_types`, `part_item_type_classes` |  |
| REQ-BSL-008 | P0 | THE SYSTEM SHALL import baselines from a spreadsheet for go-live, through the bulk import of REQ-IAM-011. |  |  |  |
| REQ-BSL-009 | P0 | WHEN an SPK that replaces a part item or tyre is submitted for approval, and again WHEN it completes, THE SYSTEM SHALL compute life used = the larger of km used ÷ normal life km and days used ÷ normal life days; IF life used is below the tolerance of its type (for tyres: the life of the position in the chassis layout and the single tyre tolerance in Settings, app\_settings.tyre\_early\_failure\_pct, set by the Planner), THEN THE SYSTEM SHALL flag Early failure on the approval review, record an early-failure event and notify the Planner, Supervisor and GM. The flag never blocks the SPK. | [`ApprovalReview`](<../../../Design Artifact/approvals/ApprovalReview.html#ApprovalReview>), [`SupervisorMobileReview`](<../../../Design Artifact/mobile/SupervisorMobileReview.html#SupervisorMobileReview>), [`Dashboard`](<../../../Design Artifact/dashboard/Dashboard.html#Dashboard>), [`NotificationCenter`](<../../../Design Artifact/shell/NotificationCenter.html#NotificationCenter>) | `early_failure_events`, `part_item_types.early_failure_pct` |  |

| ID | Verifies | Acceptance criterion |
| --- | --- | --- |
| AC-BSL-001 | REQ-BSL-004 | WHEN an oil filter was replaced at 10.100 km with a 10.000 km life, next due SHALL be 20.100 km. |
| AC-BSL-002 | REQ-BSL-002 | WHEN baseline tyres are saved, they SHALL show on both the Part Replacement map and the Vehicles map. |
| AC-BSL-003 | REQ-BSL-004 | A part item without a baseline SHALL raise no alert. |
| AC-BSL-004 | REQ-BSL-005 | IF Correct baseline is used on a part item that a completed SPK reset, THEN THE SYSTEM SHALL refuse. |
| AC-BSL-005 | REQ-BSL-009 | WHEN front brake pads with a normal life of 40.000 km and 365 days are replaced after 18.000 km and 120 days (life used 45%, tolerance 80%), THE SYSTEM SHALL flag Early failure on the review, notify the Planner, Supervisor and GM, and the SPK SHALL still be approvable. |
