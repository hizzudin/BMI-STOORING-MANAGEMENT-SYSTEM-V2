# 4.19 NTF: notifications (P0 in-app, push P0 for the R1 mobile roles, P1 for the rest)

> Part of the BMI Stooring System spec (§4 functional requirements, area NTF). Core rules, roles, state machines, business rules and decisions: [PRD.md](../../../PRD.md). Section numbers and IDs are unchanged from the single-file PRD v2.4.


| ID | P | Requirement | Screens | Data | Rules |
| --- | --- | --- | --- | --- | --- |
| REQ-NTF-001 | P0 | THE SYSTEM SHALL create an in-app notification for: approval waiting, step opened, step returned, SPK rejected, change request, alert, schedule change; the bell in the page header SHALL open a list with read and unread state, and each notice SHALL open the record it names. | [`NotificationCenter`](<../../../Design Artifact/shell/NotificationCenter.html#NotificationCenter>) | `notifications` |  |
| REQ-NTF-002 | P1 | WHEN an in-app notification is created, THE SYSTEM SHALL also push it (P0 for the roles of the R1 step 7 app: Driver, Field Coordinator, Mechanic, System Admin, DEC-98; P1 for the rest) to every phone where the user is signed in to the mobile app; tapping it SHALL open the matching screen. | [`DispatcherMobileAlerts`](<../../../Design Artifact/mobile/DispatcherMobileAlerts.html#DispatcherMobileAlerts>), [`SupervisorMobileHome`](<../../../Design Artifact/mobile/SupervisorMobileHome.html#SupervisorMobileHome>) | `push_devices`, `notification_deliveries` |  |
| REQ-NTF-003 | P1 | THE SYSTEM SHALL let a user mute push per kind in Profile; the in-app notification SHALL stay. | mobile Profile | `notification_mutes` |  |
| REQ-NTF-004 | P2 | WHERE the WhatsApp or email adapter is enabled, THE SYSTEM SHALL send the same notifications on that channel. |  | `notification_deliveries.channel` |  |
| REQ-NTF-005 | P0 | THE SYSTEM SHALL send each event to exactly the recipients and channels of the notification matrix below this table. | [NotificationCenter](<../../../Design Artifact/shell/NotificationCenter.html#NotificationCenter>) | notifications | - |

**Notification matrix (REQ-NTF-005).** Each event goes to exactly these recipients; push goes only to roles that have the mobile app in that release (4.20).

| Event | Recipients | Channel |
| --- | --- | --- |
| SPK submitted for approval (creation, amendment, completion) | Supervisors, GM, System Admin; Planners while Planner approval covers it | In-app, push |
| SPK approved, rejected or cancelled | Creator; executor of the open step | In-app, push |
| Step opened | Executor roles of the step (Stock: Warehouse Manager; Part Purchase: Field Coordinators and System Admin) | In-app, push |
| Step submitted | Planners and System Admin (verifiers) | In-app |
| Step returned | Executor of the step | In-app, push |
| Change request submitted, decided | SPK creator and Approvers; then the requester | In-app, push |
| Report Breakdown sent, also from an inspection Fail | Field Coordinators, Planners, System Admin | In-app, push |
| Urgent Report Breakdown from a Driver, or entered for one | Planners: the blocking pop-up of REQ-BRK-004, as well as the row above | Pop-up |
| Report Breakdown rejected, or an SPK made from it | Reporter | In-app, push |
| PM, part item, tyre, document alert | Planners, System Admin | In-app |
| Early failure | Planners, Supervisors, GM | In-app |
| Schedule card placed, moved, missed; today's list | Field Coordinators | In-app, push |
| Stock opname or tyre count submitted | Supervisors, GM, System Admin (and Planners if ticked) | In-app |
| Low stock, overdue retread | Warehouse Manager | In-app |
| Planner approval switched on or off | Supervisors, GM | In-app |
| Invoice draft created, invoice overdue | Accounting, Supervisors | In-app |
| SPK late (planned day passed, not Completed), daily | SPK creator, executor of the open step, Planners, Field Coordinators, GM | In-app, push |
| Step assigned, reassigned, claimed or released | New assignee; previous assignee on a reassign; Planners when an assignee releases a step | In-app, push |
| Parts of a cancelled SPK to receive | Warehouse Manager | In-app |
| Driver of a vehicle changed | New and previous driver | In-app, push |
