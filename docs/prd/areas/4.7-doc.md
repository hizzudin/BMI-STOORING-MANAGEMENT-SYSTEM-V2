# 4.7 DOC: vehicle documents (P0)

> Part of the BMI Stooring System spec (§4 functional requirements, area DOC). Core rules, roles, state machines, business rules and decisions: [PRD.md](../../../PRD.md). Section numbers and IDs are unchanged from the single-file PRD v2.4.


Goal: keep every required document valid and block a vehicle from trips when one is Missing or Expired. States: `SM-DOC` (3.5).

| ID | P | Requirement | Screens | Data | Rules |
| --- | --- | --- | --- | --- | --- |
| REQ-DOC-001 | P0 | THE SYSTEM SHALL track STNK annual, STNK five-year, KIR (six-monthly, trucks) and insurance, plus any type in master data; which types are required comes from the vehicle class. | [`DocumentTypes`](<../../../Design Artifact/settings/MasterData.html#DocumentTypes>) | `document_types` |  |
| REQ-DOC-002 | P0 | THE SYSTEM SHALL let the System Admin maintain document types: code, name, usual validity in months, warning days (default 30; the only place warning days are set), whether a renewal receipt is required, and the classes that need it; WHEN the required classes change, THE SYSTEM SHALL show how many vehicles become non-compliant before saving. | [`DocumentTypes`](<../../../Design Artifact/settings/MasterData.html#DocumentTypes>) | `document_types` |  |
| REQ-DOC-003 | P0 | WHEN the daily check runs, THE SYSTEM SHALL set Warning at expiry minus the type's warning days, Expired on the expiry date, and Missing for a required type with no row. | [`Documents`](<../../../Design Artifact/documents/Documents.html#Documents>), [`VehicleDocuments`](<../../../Design Artifact/fleet/Vehicle.html#VehicleDocuments>) | `vehicle_documents.status` |  |
| REQ-DOC-004 | P0 | WHEN a document enters Warning, THE SYSTEM SHALL create exactly one Draft SPK of the Document category for it (never a duplicate), which follows normal approval. | [`Documents`](<../../../Design Artifact/documents/Documents.html#Documents>) | `uq_open_document_spk` | BR-04 |
| REQ-DOC-005 | P0 | WHILE a required document is Missing or Expired, THE SYSTEM SHALL show the vehicle Blocked and refuse to assign it to trips; it MAY still be placed on the maintenance schedule. | [`Vehicles`](<../../../Design Artifact/fleet/Vehicles.html#Vehicles>), [`DashboardDispatcher`](<../../../Design Artifact/dashboard/Dashboard.html#DashboardDispatcher>) | `vehicles.status` | BR-08 |
| REQ-DOC-006 | P0 | THE SYSTEM SHALL lift the block in exactly one of three ways: first entry of a never-entered document ([`AddDocument`](<../../../Design Artifact/documents/DocumentForm.html#AddDocument>) or the Add vehicle form); "Correct entry" by the System Admin of a wrong first entry; renewal through a Document SPK. | [`AddDocument`](<../../../Design Artifact/documents/DocumentForm.html#AddDocument>), [`DocumentCorrectEntry`](<../../../Design Artifact/documents/DocumentForm.html#DocumentCorrectEntry>), [`DocStep`](<../../../Design Artifact/steps/DocStep.html#DocStep>) |  | BR-01 |
| REQ-DOC-007 | P0 | WHEN the System Admin submits the Document step, THE SYSTEM SHALL require number, issue date, new expiry (later than the old one; prefilled as the issue date plus the type's usual validity in months, editable, DEC-80), scan, renewal cost (Rp) and, where the type requires it, a receipt image; WHEN the step is verified, the new expiry SHALL apply, the status SHALL be recalculated, the cost SHALL be added to the SPK and the old record SHALL be kept as history. | [`DocStep`](<../../../Design Artifact/steps/DocStep.html#DocStep>) | `document_renewals`, `spks.document_cost` |  |
| REQ-DOC-008 | P0 | THE SYSTEM SHALL let the System Admin enter a document for the first time without an SPK (number, issuer, issue date, expiry date, scan), preview the status it will get, list the documents still required, save a past expiry as Expired, and write an audit record. | [`AddDocument`](<../../../Design Artifact/documents/DocumentForm.html#AddDocument>), [`AddVehicle`](<../../../Design Artifact/fleet/VehicleForm.html#AddVehicle>) | `vehicle_documents`, `audit_logs` | BR-01 |
| REQ-DOC-009 | P0 | WHILE no renewal SPK exists for a document, THE SYSTEM SHALL let the System Admin correct its number, dates or scan with a reason ("Correct entry"), logging each field's old and new value; IF a renewal exists, THEN it SHALL refuse and a wrong value is fixed by a change request on that SPK. | [`DocumentCorrectEntry`](<../../../Design Artifact/documents/DocumentForm.html#DocumentCorrectEntry>) | `document_corrections` |  |
| REQ-DOC-010 | P0 | THE SYSTEM SHALL let a Document step change only documents of its SPK's vehicle. | [`DocStep`](<../../../Design Artifact/steps/DocStep.html#DocStep>) |  | BR-02 |
| REQ-DOC-011 | P0 | THE SYSTEM SHALL show a matrix of vehicles by document type (one status per cell, vehicle status column), a detail panel with renewal history, View scan and Open SPK; View scan shows every scan version with zoom, rotate and download, and logs every view. | [`Documents`](<../../../Design Artifact/documents/Documents.html#Documents>), [`VehicleDocuments`](<../../../Design Artifact/fleet/Vehicle.html#VehicleDocuments>), [`DocumentScan`](<../../../Design Artifact/documents/Documents.html#DocumentScan>) | `document_view_logs` |  |
| REQ-DOC-012 | P0 | WHEN a document is Expired, THE SYSTEM SHALL remind the driver not to operate the vehicle: on the dashboards and the Field Coordinator views in release 1, in the mobile app from R1 step 7. | [`DashboardDispatcher`](<../../../Design Artifact/dashboard/Dashboard.html#DashboardDispatcher>), [`DashboardDriver`](<../../../Design Artifact/mobile/FieldReports.html#DashboardDriver>) | `notifications` |  |
